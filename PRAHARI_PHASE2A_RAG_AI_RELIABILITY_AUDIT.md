# Phase 2A — RAG & AI Reliability Audit

This report document contains the complete audit and diagnostic findings regarding RAG retrieval quality, domain isolation, authority contact hallucinations, and risk inferences in Prahari.

---

## 1. Executive Summary

A real-world end-to-end smoke test of `openai/gpt-oss-120b` exposed several critical AI and RAG reliability problems:
1. **Irrelevant Recommendations**: A mass-shooting emergency signal recommended tenancy-related evidence (such as rent agreements, lease deeds, and locked door photographs).
2. **Contact Hallucination**: Authority contact details generated by the LLM contained unverified placeholder values (like `01234-567890` and `1800-HOME-SEC`).
3. **Self-Harm Inference**: The agent inferred a "risk of self-harm" solely from a user reporting general nervous distress.

This audit traced these behaviors to their exact architectural roots. We identified client-side hardcoding bugs, lack of vector distance thresholds, domain cross-contamination, and a total absence of a verified contact database. **No application code was modified during this audit.**

## 2. Complete RAG Architecture

The Prahari RAG architecture operates through three primary phases:

### A. Ingestion Phase
- **Legal Provisions**: [`rag/ingest.py`](file:///d:/My%20Projects/Django/Prahari/rag/ingest.py) (`ingest_legal_documents()`) deletes and recreates the `legal_provisions` collection. Chunks are ingested with metadata (`category`, `act`, `section`).
- **Medical Protocols**: [`rag/ingest.py`](file:///d:/My%20Projects/Django/Prahari/rag/ingest.py) (`ingest_medical_protocols()`) deletes and recreates the `medical_protocols` collection.
- **Incident History**: [`pipeline/tasks.py`](file:///d:/My%20Projects/Django/Prahari/pipeline/tasks.py) calls `ingest_incident_to_history()`, which embeds and upserts the `situation_brief` into the `incident_history` collection.
- **Embedder**: All documents are embedded locally using `sentence-transformers/all-MiniLM-L6-v2` (`SentenceTransformerEmbeddingFunction`).

### B. Retrieval Phase
- **Query Processing**: [`rag/retriever.py`](file:///d:/My%20Projects/Django/Prahari/rag/retriever.py) houses the retrieval helpers:
  - `retrieve_legal_provisions(query, n_results=3)`
  - `retrieve_medical_protocols(query, n_results=3)`
  - `retrieve_similar_incidents(query, n_results=3, exclude_id=None)`
- **Distance Metric**: Uses ChromaDB's default L2 squared distance metric.

### C. LLM Generation Phase
- **Context Injection**: [`apps/agents/agents.py`](file:///d:/My%20Projects/Django/Prahari/apps/agents/agents.py):
  - `TriageAgent.run()` queries `retrieve_medical_protocols` and appends the raw text directly to the system/user prompt.
  - `RightsAgent.run()` queries `retrieve_legal_provisions` and appends the raw text directly to the system/user prompt.
  - `CoordinationAgent.run()` gathers outputs from all agents and prompts the LLM to synthesize them.

## 5. Retrieval Configuration

- **Relevance Metrics**: L2 squared distance is returned by ChromaDB.
- **Enforced Thresholds**: **None**. There is no minimum similarity or maximum distance boundary enforced. `retrieve_legal_provisions()` and `retrieve_medical_protocols()` slice the first `n_results` returned by ChromaDB's L2 query, making retrieval completely top-k bounded regardless of actual document distance.

---

## 6. RAG Relevance Analysis

Because no similarity threshold is enforced:
1. Every query always returns exactly `n_results` chunks.
2. Even in highly irrelevant queries (e.g., `mass-shooting` compared against eviction laws), the model is forced to digest the returned text.
3. The LLM prompts do not instruct the model to discard irrelevant context.

## 7. Investigation of Irrelevant Rent Documents

The recommending of tenancy evidence (lease agreements, rent receipts) during a mass-shooting report was traced to a **critical client-side rendering bug** in [`templates/report_status.html`](file:///d:/My%20Projects/Django/Prahari/templates/report_status.html):

```javascript
function bringChecklist(domain, nearest_authority_type, title, brief, lang = 'en') {
    ...
    const isTenantDispute = textToMatch.includes('evict') || textToMatch.includes('tenant') || textToMatch.includes('rent') || textToMatch.includes('landlord') || textToMatch.includes('lease');
    ...
    if (auth === 'Police Complaint Authority' || ...) {
        key = 'fir_refusal';
    } else if (isTenantDispute || auth === 'DLSA' || auth === 'Magistrate Court') {
        key = 'eviction';
    }
    ...
```

- **Mechanism**: The `RightsAgent` or `CoordinationAgent` fallback defaulted `nearest_authority_type` to `"DLSA"`.
- **Bug**: The Javascript `bringChecklist` logic checks `auth === 'DLSA'`. Since that evaluates to true, it hardcodes the displayed evidence checklist category `key` to `"eviction"`.
- **Result**: The UI rendered the static checklist associated with `"eviction"` (rent agreement, lease deed, locked door photos) for a violent emergency report.

## 8. Authority Contact Data Flow

The flow of authority contacts is entirely unstructured:
```
  [LLM Prompt] ──(No Contact Data Passed)──> [openai/gpt-oss-120b] ──(Hallucinates Strings)──> [Incident.agent_outputs] ──> [UI/PDF Render]
```

Prahari has no master database, directory, or CSV file containing verified authority contacts (such as phone numbers, emails, or office hours).

---

## 9. Placeholder Contact Investigation

- **Evidence**: The system prompts do not contain placeholder numbers. However, they mandate that the model output the `contact` field under `escalation_path` and `authority_to_contact`.
- **Hallucination Cause**: To satisfy the JSON schema string contracts, the LLM (`openai/gpt-oss-120b`) hallucinates fake helpline formats (such as `01234-567890` or `1800-HOME-SEC`) since it has no actual directory context.
- **Verification**: The application treats these strings as validated facts; no verification or parsing is applied before display.

## 10. Self-Harm Inference Investigation

- **Evidence**: In [`rag/ingest.py`](file:///d:/My%20Projects/Django/Prahari/rag/ingest.py#L670-L684), `mental_health_protocol` is defined and ingested. It details: *"This protocol applies to individuals experiencing acute psychiatric distress, self-harm ideation, or behavioral dysregulation."*
- **Mechanism**: The user reported feeling "nervous/distressed" during the emergency. This matched the embeddings of `mental_health_protocol` (Category: psychiatric_care).
- **Contamination**: Because there is no relevance threshold, this protocol was injected into the `TriageAgent`'s prompt context.
- **Hallucination**: The LLM digested this context alongside the user's distress and concluded there was an active risk of self-harm. The agent does not distinguish general situational anxiety from suicide risk.

---

## 11. Emergency Priority Analysis

- **Mechanism**: The prioritization of emergency actions is primarily directed by textual instructions in `prompts/coordination.txt` (e.g. *"medical actions must always occupy priority slots 1 and 2"*).
- **Code Sort**: [`apps/agents/agents.py`](file:///d:/My%20Projects/Django/Prahari/apps/agents/agents.py#L387) executes:
  `validated_actions.sort(key=lambda x: x["priority"])`
- **Result**: Prioritization is LLM-dependent. There is no deterministic safety override to guarantee that life-saving interventions remain at the top if the LLM fails to order them properly.

---

## 12. Multi-Agent Data Flow

The sequential data flow follows:
```
  Citizen Input -> SentinelAgent -> TriageAgent / RightsAgent -> CoordinationAgent -> LanguageAgent -> LegalNoticeAgent
```

- **Conflict Risk**: `CoordinationAgent` acts as an LLM consolidator. Because it re-summarizes findings into a single situation brief and response plan, it can overwrite, ignore, or contradict the specific clinical/legal decisions made by `TriageAgent` or `RightsAgent`.

## 18. Recommended Phase 2 Roadmap

1. **Fix Evidence Checklist**: Refactor `bringChecklist()` javascript to prevent false eviction classification.
2. **Enforce RAG Distance Thresholds**: Set distance limits on `retrieve_legal_provisions` and `retrieve_medical_protocols`.
3. **Master Directory Injection**: Create a static data structure of verified district-level helplines and inject them into `BaseAgent` templates during context assembly, preventing LLM phone number hallucination.
4. **Prompt Tuning**: Refine `triage.txt` and `rights.txt` instructions to prevent false self-harm or constitutional claims.
